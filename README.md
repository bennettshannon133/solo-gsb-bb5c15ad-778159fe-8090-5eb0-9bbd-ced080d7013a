# 设备停机原因分析（故障树最小割集 + 现场诊断）

供设备检修人员分析停机原因的网页工具：录入至多 **12 个基础故障**与引用基础故障/其他门的 **AND、OR 门**，指定**顶层故障**后，系统自底向上计算使顶层故障发生的**最小基础故障组合**（故障树最小割集 MCS）。

- **AND 门**：合并各输入的子组合（笛卡尔积），同一基础故障重复出现只算一次；
- **OR 门**：汇总各输入的子组合；
- 每一步都**去重并删除包含更小组合的超集**，共享子树记忆化，避免重复路径放大结果；
- 结果按**故障数升序、名称字典序**排序，并列出每个组合涉及的基础故障。

此外支持**现场诊断**：为每个基础故障录入**独立先验发生概率（0～1）**，并可将故障标记为**已确认发生 / 已确认未发生**；在「顶层故障确已发生」的前提下，计算每个**未确认**基础故障的**后验发生概率**并按概率降序展示，辅助现场排查顺序：

- **精确枚举**全部 2ⁿ（n ≤ 12）个与现场标记一致的状态组合，不做任何独立性近似；
- 每个组合按 AND/OR 门求顶层状态并计算联合概率，**共享引用**（同一故障被多个门引用）在同一组合内只取一个确定状态，**不会把共享分支当作独立事件相乘**；
- 只保留顶层发生的组合，按**条件概率归一化**得到后验概率；
- 若**证据概率为零**（与标记一致且顶层发生的组合不存在），明确提示**观测与模型矛盾**。

## 一条命令启动（推荐）

已安装 Docker Engine 与 Compose 插件（Docker Desktop / Docker Engine 20.10+）：

```bash
docker compose up --build -d
```

启动后浏览器访问：

> **http://localhost:3000**

依赖安装、应用初始化均包含在镜像构建与容器启动过程中，无需其他手动步骤。
停止服务：`docker compose down`；查看日志：`docker compose logs -f`。

## 配置

通过 Compose 的环境变量 / 端口映射配置（见 `docker-compose.yml`）：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 容器内监听端口，一般无需修改 |
| 端口映射 | `3000:3000` | 宿主机端口被占用时改为如 `8080:3000`，然后访问 http://localhost:8080 |
| `NODE_ENV` | `production` | 运行环境 |

本工具不依赖数据库，无需配置账号密码或外部服务。

## 本地直接运行（无 Docker 时）

要求 Node.js ≥ 20：

```bash
npm install
npm start
```

访问 http://localhost:3000 。运行测试（零额外测试依赖，使用 Node 内置 test runner）：

```bash
npm test
```

## 使用说明

1. **基础故障**：填写不可再分的故障名称（如「主电源中断」），最多 12 个，名称不可重复；并在每行右侧录入该故障的**独立先验发生概率**（0～1，供现场诊断使用）。
2. **逻辑门**：新建 AND / OR 门并命名；通过多选标签勾选该门的输入，输入可引用基础故障或其他门（门不能引用自身）。
3. **顶层故障**：在下拉框中选择要分析的停机事件。
4. 点击 **分析停机原因**。页面列出全部最小基础故障组合，每组标注故障数量并展示具体故障名称。
   也可点击右上角 **载入示例** 快速体验。
5. **现场诊断**：在第 4 步中将现场已确认的基础故障标记为「已确认发生 / 已确认未发生」（默认未确认），点击 **计算后验概率**。页面按后验概率降序列出各未确认故障，并给出证据概率与枚举的状态组合数；若标记与模型矛盾（证据概率为零），会显示醒目的警示。

以下情况会给出明确中文错误（一次性列出全部问题）：

- 门引用了**不存在**的基础故障或门；
- 门之间**成环**（含门引用自身）；
- **未指定**顶层故障，或顶层故障不存在；
- 基础故障超过 12 个、名称重复、门名称缺失/重名、门类型非法、门没有输入等。

## 接口

### 最小割集分析

`POST /api/analyze`

请求体：

```json
{
  "basicFaults": ["主电源中断", "备用电源失效"],
  "gates": [
    { "id": "供电失效", "type": "OR", "inputs": ["主电源中断", "备用电源失效"] }
  ],
  "topEvent": "供电失效"
}
```

成功响应：

```json
{
  "ok": true,
  "topEvent": "供电失效",
  "count": 2,
  "combinations": [["主电源中断"], ["备用电源失效"]]
}
```

输入非法时返回 HTTP 400：`{ "ok": false, "errors": ["……"] }`。

### 现场诊断

`POST /api/diagnose`

请求体（故障树结构与 `/api/analyze` 相同，校验规则完全一致；新增 `priors` 与 `evidence`）：

```json
{
  "basicFaults": ["主电源中断", "备用电源失效"],
  "gates": [
    { "id": "供电失效", "type": "OR", "inputs": ["主电源中断", "备用电源失效"] }
  ],
  "topEvent": "供电失效",
  "priors": { "主电源中断": 0.02, "备用电源失效": 0.05 },
  "evidence": { "备用电源失效": "absent" }
}
```

- `priors`：每个基础故障的独立先验发生概率，0～1 的数值，**每个基础故障必填**；
- `evidence`：现场标记，`"occurred"`（已确认发生）/ `"absent"`（已确认未发生），可缺省或部分提供，未列出的故障视为未确认。

成功响应（HTTP 200，`posteriors` 仅含未确认故障，按后验概率降序）：

```json
{
  "ok": true,
  "topEvent": "供电失效",
  "evidenceProbability": 0.019,
  "statesEnumerated": 2,
  "posteriors": [
    { "name": "主电源中断", "probability": 1.0 }
  ]
}
```

- `evidenceProbability`：与现场标记一致且顶层发生的状态组合的联合概率之和（归一化分母）；
- `statesEnumerated`：参与枚举的、与现场标记一致的状态组合数。

**观测与模型矛盾**（证据概率为零，例如 AND 门的输入被标记为「已确认未发生」）时返回 HTTP 422：

```json
{ "ok": false, "contradiction": true, "errors": ["证据概率为零：……观测与模型矛盾。……"] }
```

输入非法（结构错误、先验缺失/越界、标记指向未定义故障等）时返回 HTTP 400：`{ "ok": false, "errors": ["……"] }`。

健康检查：`GET /api/health` → `{"status":"ok"}`。
