# 设备停机原因分析（故障树最小割集 + 现场诊断）

供设备检修人员分析停机原因的网页工具：录入至多 **12 个基础故障**与引用基础故障/其他门的 **AND、OR 门**，指定**顶层故障**后，系统自底向上计算使顶层故障发生的**最小基础故障组合**（故障树最小割集 MCS）。

- **AND 门**：合并各输入的子组合（笛卡尔积），同一基础故障重复出现只算一次；
- **OR 门**：汇总各输入的子组合；
- 每一步都**去重并删除包含更小组合的超集**，共享子树记忆化，避免重复路径放大结果；
- 结果按**故障数升序、名称字典序**排序，并列出每个组合涉及的基础故障。

## 现场诊断（后验概率定位）

在最小割集分析之上，工具支持**已知顶层故障确已发生**时的现场诊断：

- 为每个基础故障录入**独立先验发生概率**（0～1）；
- 现场已排查的故障可标记为**已确认发生**或**已确认未发生**，其余保持未确认；
- 系统**精确枚举**全部与现场标记一致的基础故障状态组合（2^n，n ≤ 12），
  对每个组合按 AND/OR 门求顶层状态、按独立先验求联合概率，
  **只保留顶层发生的组合后按条件概率归一化**，得到每个未确认基础故障的
  **后验发生概率** P(故障｜顶层发生 ∧ 现场标记)，并按概率降序展示；
- 枚举的对象是基础故障状态而非门事件，**共享分支不会被当作独立事件重复相乘**；
- 若现场标记（或其与顶层发生的组合）的概率为 0，提示**观测与模型矛盾**。

## 一条命令启动（推荐）

已安装 Docker Engine 与 Compose 插件（Docker Desktop / Docker Engine 20.10+）：

```bash
docker compose up --build -d
```

启动后浏览器访问：

> **http://localhost:3000**

依赖安装、应用初始化均包含在镜像构建与容器启动过程中，无需其他手动步骤。
停止服务：`docker compose down`；查看日志：`docker compose logs -f`。

## 配置

通过 Compose 的环境变量 / 端口映射配置（见 `docker-compose.yml`）：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 容器内监听端口，一般无需修改 |
| 端口映射 | `3000:3000` | 宿主机端口被占用时改为如 `8080:3000`，然后访问 http://localhost:8080 |
| `NODE_ENV` | `production` | 运行环境 |

本工具不依赖数据库，无需配置账号密码或外部服务。

## 本地直接运行（无 Docker 时）

要求 Node.js ≥ 20：

```bash
npm install
npm start
```

访问 http://localhost:3000 。运行测试（零额外测试依赖，使用 Node 内置 test runner）：

```bash
npm test
```

## 使用说明

1. **基础故障**：填写不可再分的故障名称（如「主电源中断」），最多 12 个，名称不可重复；
   同时为每个故障填写**独立先验发生概率**（0～1），现场已排查的故障可在下拉框中标记
   **已确认发生 / 已确认未发生**（默认未确认）。
2. **逻辑门**：新建 AND / OR 门并命名；通过多选标签勾选该门的输入，输入可引用基础故障或其他门（门不能引用自身）。
3. **顶层故障**：在下拉框中选择要分析的停机事件。
4. 点击 **分析停机原因**。页面列出全部最小基础故障组合，每组标注故障数量并展示具体故障名称。
5. 点击 **现场诊断（已知顶层故障发生）**。页面按后验概率降序列出各未确认基础故障，
   并给出 P(现场标记)、P(顶层发生 ∧ 现场标记) 与参与枚举的状态组合数；
   若观测与模型矛盾（证据概率为 0），会给出明确提示。
   也可点击右上角 **载入示例** 快速体验。

以下情况会给出明确中文错误（一次性列出全部问题）：

- 门引用了**不存在**的基础故障或门；
- 门之间**成环**（含门引用自身）；
- **未指定**顶层故障，或顶层故障不存在；
- 基础故障超过 12 个、名称重复、门名称缺失/重名、门类型非法、门没有输入等。

## 接口

### `POST /api/analyze`（最小割集）

请求体：

```json
{
  "basicFaults": ["主电源中断", "备用电源失效"],
  "gates": [
    { "id": "供电失效", "type": "OR", "inputs": ["主电源中断", "备用电源失效"] }
  ],
  "topEvent": "供电失效"
}
```

成功响应：

```json
{
  "ok": true,
  "topEvent": "供电失效",
  "count": 2,
  "combinations": [["主电源中断"], ["备用电源失效"]]
}
```

输入非法时返回 HTTP 400：`{ "ok": false, "errors": ["……"] }`。

### `POST /api/diagnose`（现场诊断）

在 `/api/analyze` 的故障树结构之上附加每个基础故障的先验概率与现场标记：

```json
{
  "basicFaults": ["主电源中断", "备用电源失效"],
  "gates": [
    { "id": "供电失效", "type": "OR", "inputs": ["主电源中断", "备用电源失效"] }
  ],
  "topEvent": "供电失效",
  "priors": { "主电源中断": 0.02, "备用电源失效": 0.05 },
  "evidence": { "主电源中断": "unknown", "备用电源失效": "absent" }
}
```

- `priors`：每个基础故障**必填**，0～1 的独立先验发生概率（数字或数字字符串）；
- `evidence`：可缺省；取值 `occurred`（已确认发生）/ `absent`（已确认未发生）/ `unknown`（未确认，缺省等同）。

成功响应（`results` 只含未确认故障，按后验概率降序）：

```json
{
  "ok": true,
  "topEvent": "供电失效",
  "evidenceProbability": 0.95,
  "topProbability": 0.019,
  "stateCount": 2,
  "topStateCount": 1,
  "confirmed": [{ "name": "备用电源失效", "status": "absent", "statusText": "已确认未发生" }],
  "results": [{ "name": "主电源中断", "prior": 0.02, "posterior": 1 }]
}
```

字段说明：`evidenceProbability` = P(现场标记)；`topProbability` = P(顶层发生 ∧ 现场标记)；
`stateCount` / `topStateCount` = 与现场标记一致的状态组合数 / 其中顶层发生的组合数。

错误响应：

- 输入非法（结构、先验、标记取值等）：HTTP 400 `{ "ok": false, "errors": ["……"] }`；
- **观测与模型矛盾**（证据概率为 0，无法归一化）：HTTP 409
  `{ "ok": false, "contradiction": true, "errors": ["观测与模型矛盾：……"] }`。

健康检查：`GET /api/health` → `{"status":"ok"}`。
